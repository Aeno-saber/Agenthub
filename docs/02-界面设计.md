## 1. 设计目标

三句话：

1. **单成员用起来像 ChatGPT** —— 内容列居中、两侧留白、输入框居中，一眼就知道怎么用。
2. **多成员能同时盯住** —— 并排分屏，每个成员一个独立面板，各自的对话和状态互不干扰。
3. **代码和产物触手可及** —— 右侧常驻可折叠的编辑器区，agent 改了什么文件当场能看。

设计取向：**克制**。扁平、细边框、无阴影无渐变，让内容（对话和代码）当主角。

> ⚠️ 上面这条"无阴影无渐变"已被**修订 2 / 3 / 5 连续推翻**，现行口径见文末修订 5：
> 表面分四层（底/卡/次级/凹陷）、阴影三档、渐变只给品牌与主操作按钮，
> 会话正文区仍然保持"内容当主角"。本文正文保留原样是为了留下决策轨迹。

## 3. 区域规格

### 3.1 顶栏

高度 36px，底边框分隔。左到右：

| 元素 | 说明 |
|---|---|
| 产品名 | `AgentHub` |
| 项目选择器 | 当前工作目录/项目，点击切换 |
| 权限档位 | 药丸形按钮，点击切换只读 / 计划 / 执行。**当前档位直接显示在按钮上** |
| 编辑器开关 | 图标按钮，亮起=展开，暗=收起。状态与编辑器面板实时联动 |
| 成员计数 | `成员 2/7`，点击打开成员管理 |

**注意**：权限档位是全局默认值，但每个会话面板头部还能单独覆盖（见 §4.2）。

### 3.2 左栏（三档可收起）

| 档位 | 宽度 | 何时使用 |
|---|---|---|
| **完整** | 156px | 单会话模式，或窗口足够宽 |
| **图标条** | 44px | 并排 ≥2 面板时自动切换 |
| **隐藏** | 0 | 手动全屏时 |

完整态内容（自上而下）：

```
[新建会话] [新建协同]          ← 并排两个等宽按钮
独立会话
  ● Claude          ← 选中项有底色
  ● Qoder
  ● 豆包
协同任务
  ● 给 utils 加单测
```

- 每项左侧一个 6px 状态圆点（颜色见 §6）
- 会话名超长用省略号截断，不换行
- 图标条态只保留三条横线的展开按钮 + 新建 + 设置三个图标

### 3.3 主区（三选一视图）

主区是一个容器，根据当前选中项渲染三种视图之一。详见 §4。

### 3.4 编辑器区

默认宽 184px，**可拖拽调整 160~520px**。

```
编辑器       utils.js ●      保存    收起     ← 标题行（● = 未保存）
─────────────────────────────
src/                             ← 文件树
  utils.js        ← 当前选中（高亮）
  index.js
tests/
  utils.test.js
─────────────────────────────
export const clamp =             ← 编辑区，可直接改（等宽字体）
  (v, min, max) =>
    Math.min(max,
      Math.max(min, v))
─────────────────────────────
⚠ Claude 正在修改此文件           ← 占用提示（有人改时出现）
```

**支持编辑**，但必须处理三件事 —— 因为 agent 也在改同一批文件：

1. **未保存标记**：文件名后一个小圆点，有改动就亮
2. **保存**：`Ctrl+S`，或标题行「保存」按钮
3. **冲突处理（关键）**：不防就会互相覆盖
   - 打开文件时记下 mtime + 内容 hash
   - 保存前重新比对，若文件已被外部改过 → **不直接覆盖**，弹冲突卡片
   - 冲突卡片三选项：**保留我的** / **用 agent 的** / **并排看差异**
   - 编辑期间若引擎报告某成员正在改这个文件，顶部显示占用提示，保存时同样走冲突流程

语法高亮做**基础版**（js/ts/python/json），不做 LSP、不做补全 —— 那是 IDE 的活。

收起后变成右边缘 26px 宽的窄条，只留一个 `‹` 展开按钮（见 §5）。

## 4. 主区三种视图

### 4.1 单会话（ChatGPT 风格）

**触发**：左栏点单个"独立会话"，或并排里只剩一个面板。

```
        ┌──────────────────────────────┐
        │  Claude  sonnet  (计划档)      │  ← 面板头，居中
        ├──────────────────────────────┤
        │                              │
        │              给 utils 加单测 →│  ← 用户消息右对齐，浅底气泡
        │                              │
        │ │ 读取 src/utils.js           │  ← 工具调用，左侧细竖线
        │                              │
        │ 已生成 8 个用例…              │  ← 助手消息，无气泡直接文本
        │                              │
        ├──────────────────────────────┤
        │  ┌────────────────────────┐  │
        │  │ 输入指令…  计划档·不改文件│  │  ← 输入框居中，圆角
        │  └────────────────────────┘  │
        └──────────────────────────────┘
```

关键规格：
- **内容列最大宽度 720px，水平居中**。窗口再宽也不铺满，这是 ChatGPT 观感的核心。
- 用户消息：右对齐，浅底圆角气泡
- 助手消息：左对齐，**无气泡**，纯文本，行高 1.7
- 工具调用：左侧 2px 竖线 + 小字，默认折叠成一行
- 输入框：居中，圆角，右侧显示当前档位提示

### 4.2 并排会话

**触发**：新建会话时选多个成员，或把左栏会话拖进主区。

```
   ┌────────────────┐┌────────────────┐┌────────────────┐
   │ Claude  sonnet ││ Qoder   auto   ││ 豆包     seed  │
   ├────────────────┤├────────────────┤├────────────────┤
   │       加单测 → ││    重构导出 →  ││   写文档 →     │
   │                ││                ││                │
   │ │ 读取 utils.js││ │ 分析 5 个函数││                │
   │                ││                ││                │
   │ 已生成 8 个用例 ││ 已拆为 3 步，   ││ 已生成 README  │
   │                ││ 第 2 步待确认   ││ 章节草稿       │
   │                ││                ││                │
   ├────────────────┤├────────────────┤├────────────────┤
   │ [输入指令…]    ││ [输入指令…]    ││ [输入指令…]    │
   └────────────────┘└────────────────┘└────────────────┘
```

规格：
- **等分列**（`minmax(0, 1fr)`），最多建议 3 列；超过 3 个提示改为标签页切换
- 每列**独立输入框、独立上下文、独立权限档**
- 列宽不足 320px 时，消息气泡自动收窄，工具调用行改省略号
- 每列头部显示：成员名 / 模型 / 权限档 / 本次花费
- 列之间 0.5px 竖线分隔

**广播输入**

- 每个面板底部输入框右下角有「发给全部」勾选框
- 勾上后，这条指令**同时发给所有列**，各列并行执行
- 此时其他面板顶部出现一条 `接收广播中` 细标记，输入框置灰
- 取消勾选立即恢复独立输入
- 广播仍然算独立会话，**不进入协同任务**——它只是批量下发，各列互不依赖

### 4.3 协同任务

**触发**：左栏点"协同任务"下的条目。

> **这一屏就是"谁主要工作、谁写文档"的可视化落点**——全在角色标签上。

主脑拆完就直接开跑是危险的。中间必须有这道闸，尤其在第一期还没有界面兜底的时候。

```

│ 目标：给 utils 模块加单测并写文档                       │

│                                                      │

│         ↓ 产出将传给 ②                                │
│ ② [Cursor ▾]  角色 [评审 ▾]            依赖 ①          │
│    审查覆盖率与边界条件，指出遗漏分支 [编辑指令] [删除]   │
│         ↓ 产出将传给 ③                                │
│ ③ [豆包 ▾]    角色 [文档书写 ▾]        依赖 ①②         │
```

规格：

- **成员**和**角色**都是下拉框，可当场改 —— 主脑派的活不一定合你意

- 「删除」移除，「+ 手动加」插一条空的自己填
- 「重拆」把目标打回去让主脑重新拆
- 权限档位在这里做二次确认，**默认继承顶栏，可单独调**
- 确认后才落盘执行

## 5. 可收起的联动规则

三块区域的收起不是各自独立的，要遵守这套规则（否则会挤成一团）：

| 条件 | 左栏 | 编辑器 |
|---|---|---|
| 单会话 + 窗口 ≥1200px | 完整 156px | 保持用户上次状态 |
| 单会话 + 窗口 <1200px | 完整 156px | 自动收起为窄条 |
| **并排 ≥2 面板** | **自动切图标条 44px** | 自动收起为窄条 |
| 并排 + 用户手动展开编辑器 | 保持图标条 | 展开 184px，对话列相应变窄 |
| 协同任务视图 | 保持用户上次状态 | 保持用户上次状态 |

原则：**用户手动操作优先于自动规则，但切换视图时重新计算**。手动展开过的区域，在当前视图内不再被自动收起。

## 6. 状态与色彩

主色沿用平台变量，状态色固定：

| 状态 | 色值 | 用在哪 |
|---|---|---|
| 运行中 | `#EF9F27`（琥珀） | 圆点、卡片边框、状态文字 |
| 已完成 | `#97C459`（绿） | 圆点、耗时文字 |
| 等待中 / 未连接 | `#888780`（灰） | 圆点、置灰卡片 |
| 失败 | `#E24B4A`（红） | 圆点、错误日志 |
| 主脑 / 人决策点 | `#EF9F27` 系 | 权限按钮、需确认提示 |

- 所有分隔线 `0.5px`，颜色 `var(--color-border-tertiary)`
- 卡片圆角 `var(--border-radius-md)`，面板圆角 `var(--border-radius-lg)`
- **不用阴影、不用渐变**

## 7. 交互细节

| 场景 | 行为 |
|---|---|
| 新建会话 | 弹出成员选择器，已安装成员可选，未安装成员置灰并注明原因 |
| 新建协同 | 只输入目标，由主脑拆解；拆完先出**执行计划表**等你确认 |
| 拖拽会话进主区 | 触达主区边缘 1/3 区域时高亮，放下即形成并排 |
| 并排超过 3 列 | 提示"建议改为标签页"，或自动把最早的列折叠成标签 |
| 切换权限档 | 只对**之后发出**的指令生效，不打断正在跑的任务 |
| 危险动作 | 弹确认卡片，显示具体命令和影响范围，红边框 |
| 子任务失败 | 卡片转红，就地给三个按钮：重试 / 换人 / 跳过 |
| 停止任务 | 二次确认，显示会被中断的子任务清单 |

## 8. 成员管理界面

从顶栏「成员 2/7」进入。

```
┌──────────────────────────────────────────────────────┐
│ 成员管理                              [+ 自定义成员]    │
├──────────────────────────────────────────────────────┤
│ ● Claude     claude.cmd        可用    默认[计划 ▾]    │
│              C:\Users\deno\bin\claude.cmd     [测试]   │
│                                                      │
│ ○ Cursor     cursor-agent      未安装  默认[计划 ▾]    │
│              查看安装方式                      [测试]   │
│                                                      │
│ ○ Qoder      qodercli          未安装  默认[计划 ▾]    │
│ ──────────────────────────────────────────────────── │
│ 自定义成员                                            │
│ ● 我的 Agent  myagent.cmd      可用    默认[执行 ▾] [编辑]│
└──────────────────────────────────────────────────────┘
```

规格：

- 每行显示：状态灯 / 名称 / 命令 / 可用性 / 该成员的**默认权限档**
- **可用性一栏必须写清原因**（未安装 / 缺密钥 / 路径不存在），不能只丢一个灰点
- 「测试」按钮实际起一次 `--version`，把原始输出显示出来 —— 不靠猜
- 未安装的成员给「查看安装方式」，直接展开对应命令

## 10. 实现状态与运行方式

### 10.1 为什么是「零依赖本地服务 + 浏览器」而不是直接上 Electron

第二期的目标是 Electron 桌面应用，但本机装了火绒实时防护：`pnpm install` 会被拖到 20~40 分钟，
还容易在"删旧目录再换新目录"那步被拦成 `拒绝访问 (os error 5)`，留下半装的 `node_modules`。

所以走**渐进路径**：先用 Node 内置模块（`http` + `fs`）把界面和引擎真正接通 —— 零依赖、秒起、随时能跑。
之后要包 Electron，只是加一层窗口壳去加载**同一个页面**，`ui/public/` 里的代码零改动。

### 10.2 跑起来

```bash
node ui/server.js --workdir D:/app/AgentHub      # 或 npm run ui
# → http://127.0.0.1:8787
```

只监听 `127.0.0.1`，不对外暴露。端口被占用会自动顺延。

**密钥要放 `.env`，不要靠 `export`。** 这个服务是长驻进程，读不到你在某个终端里 `export` 的变量 ——
实测踩过：在 shell 里带着 `DOUBAO_API_KEY` 启动能通，换个终端再启动就报「未设置密钥」，
看起来像成员配错了。复制 `.env.example` 成 `.env` 填真值即可（服务启动时会打印载入了几个变量）。

### 10.3 界面冒烟（46 条断言）

```bash
node ui/server.js --workdir D:/app/AgentHub &       # 先起服务
node tests/ui-smoke.mjs                             # 再跑冒烟
SHOT_DIR=.agenthub/shots SHOT_REAL=1 node tests/ui-smoke.mjs   # 顺带存截图（会真调 agent）
```

不用 Playwright —— 本机装带浏览器下载的依赖又慢又容易被拦。验证"界面能不能用"只需要三样东西，
Node 22 全自带：系统里的 Edge、CDP 协议（就是 WebSocket 上的 JSON-RPC）、内置的全局 `WebSocket`。

它验的不是"长得好看"，而是**会不会一打开就是空白页** —— 前端 JS 一个笔误就够让整页白掉，
而 HTTP 层怎么看都是 200。所以核心是两条：控制台有没有未捕获异常 / error 级日志，
以及 DOM 里该出现的元素在不在、**点得动**。

> **截图不是装饰，是测试手段。** 下面这个真 bug 就是截图抓出来的，代码 review 很难发现：
> 广播路径漏了一次 `render()`，点「发送」后界面**几秒钟毫无反应**，消息和忙碌态要等所有列跑完才一次性冒出来。
> 单列路径没这毛病（它有 `render()`），所以只有多列才复现。
> 发现后补了一条**零成本回归断言**（把页面 `fetch` 打桩成慢响应），并做了反证：
> 撤掉修复后正好那 3 条断言变成 `实际 0`，而「最终都拿到回复」那条**依然通过** ——
> 这正是它靠普通测试发现不了的原因。

### 10.4 安全边界

| 面 | 约束 |
|---|---|
| 网络 | 只绑 `127.0.0.1`，不监听外网 |
| 静态文件 | 只从 `ui/public/` 读，且做白名单校验（必须真在该目录内） |
| 文件读写 | 一律限制在 workdir 内，`../` 穿越直接拒绝（`safeResolveInWorkdir`） |
| 写回 | 带 mtime 冲突检测，不一致返回 409 且**不覆盖**；单文件上限 4MB |
| 成员配置写入 | 每次写前备份 `src/config/backup/members.json.bak`，写完热重载并**真探活，不过就回滚** |

## 2026-09-29 修订：首页 = 选择页（不再是广告牌）

用户原话：「首页太空了，可以把选择agent的页面分在主页上；首页agent单独和协同分开页面，按键切换，默认为选择agent单独工作」。

**问题**：原空状态只有一句"实测可用 x 个成员"加两个按钮 —— 每次开始干活都要多开一层弹窗，
最高频的动作（开单聊）被藏在二级入口里。

**改法**：

- 首页主区变成「选择页」，两个页签分开两种工作方式：
  - **单独工作（默认）**：成员卡片网格（名字 / 版本 / 默认档位 / 计费 / 能力标签）。
    **点一张卡 = 直接创建单聊，不再弹窗确认**。
    不可用成员一行带过、附原因，不占卡片位但也不消失。
    多成员并排分屏的低频入口收缩成右下角一颗「多选…」（仍走原弹窗）。
  - **协同任务**：目标输入框 + 谁来拆解（**默认选本机可用的成员**）+「拆解 / 交给主脑」，
    与「新建协同」弹窗是**同一份逻辑**（doPlan / planner-sel 处理两边都认）。
- 切换：页签按钮，或 **← / → 方向键**（两道闸：只在首页且无弹窗、焦点不在输入区时生效 ——
  在目标输入框里按 ← 是想移动光标，不是要换页）。
- 页签选择持久化（`homeTab`，存档校验，怪值回默认）。
- 「新建会话 / 新建协同」弹窗保留 —— 从已有会话里开新会话时还是要走它。

**两个设计决定，理由记在这里**：

1. **首页与弹窗的元素 id 必须是两套**（`homeGoalBox` vs `goalBox`…）。
   两者在 DOM 里可能同时在（从首页协同页签点开弹窗），`getElementById` 只认文档顺序的第一个，
   撞了 id 就是静默错对象。冒烟里有专门的断言盯着 id 泄漏。
2. **点卡片不再弹窗确认**。最高频的动作不该多一次点击；
   卡片上已经把版本 / 档位 / 计费 / 能力都写出来了，那就是确认信息本身。

变异验证（第十一轮，4 处）：默认页签改成协同 / 点卡片不开聊 / 首页用弹窗同款 id /
方向键不挡输入框焦点 —— 4 处变异各自由独立断言拦下。
（M8 与 M9/M10、M10 与 M11 有级联，不能同跑一次跑完 —— 选变异组合时要看动的是不是同一块区域。）

## 2026-09-29 修订 2：视觉质感升级（推翻本文开头的"无阴影无渐变"）

**原规格**「扁平、细边框、无阴影无渐变、让内容当主角」**按用户要求推翻**。

| 用户气泡 | 灰底 | 深色渐变气泡（和主按钮一个质感） |
| 弹窗 | 平面 | 大圆角 + 深阴影 + 遮罩模糊 |

## 2026-09-30 修订 4：删除会话 / 协同任务

用户原话：「这里没法删除会话啊」（附左栏截图，攒了三条 Claude 会话删不掉）。

**这不是 bug，是漏做的功能** —— 会话和任务只存在浏览器 localStorage 里
（后端无状态，见 `app.js` 文件头），没有删除入口就意味着**只能一直堆着**。

### 4.1 两个入口，藏的程度不一样

| 入口 | 位置 | 平时可见性 |
|---|---|---|
| 行内 `×` | 每条会话 / 任务行右侧 | 透明，**鼠标移到这一行才显形**；当前打开的那条留 55% 淡显 |
| 「清空」 | 分组标题（独立会话 / 协同任务）右侧 | **一直看得见**（45% 透明度），列表为空时整颗按钮消失 |

为什么不一样：行内 × 一屏十几个太吵，藏起来是对的；
但「清空」是**用户找不到删除时的第二条路**，也藏进悬停就等于彻底找不到
—— 这次的问题本来就是"界面上没有任何看得见的删除入口"。

### 4.2 点 × 不能顺带打开会话

点击分发用的是 `e.target.closest('[data-act]')`：点到 × 时最近的那个 `[data-act]`
就是按钮自己，所以**靠 DOM 结构**隔开两条动作，不靠 `stopPropagation`
（那种写法很容易被后续改动破坏，而且坏了没人知道）。
冒烟里有一条专门盯它：「× 没有穿透到整行（当前打开的会话没被换掉）」。

### 4.3 确认框必须说清三件事

会话是真花钱跑出来的，而且**没有回收站、没有云端副本** —— 删掉就是真没了。
按钮上写「删除」两个字，用户想不到这一层。所以对话框逐条列：

1. 会丢多少（会话：几条对话记录；任务：几个子任务、其中几个已完成）；
2. 正在跑的成员：**费用照算**，但结果不会再显示（请求已经发出去了，删不掉）；
3. **工作目录里的文件不会被删** —— 不写这条，用户会以为要连产出一起删而不敢点。

「清空」是批量操作，同样先确认，并把总数写在正文里（"清空"这个词本身不告诉你要清掉多少）。

### 4.4 三个不能省的收尾动作

删一个会话时，跟着它走的瞬态必须一起清掉：

1. **草稿** `drafts[cid:mid]`、**广播开关** `broadcast[cid]` —— 不清就是永久内存垃圾，
   而且万一将来 id 撞上，新会话会"莫名带着上次的字"；
2. 删的正好是**当前打开**的那条 → `active` 回到 blank（退回选择页）。
   否则 `render()` 找不到会话，主区白屏；
3. 立刻 `saveState()` —— 用户下一秒可能就刷新页面。

（第 1 条是变异 M16 的靶子：注释掉清理那行，冒烟精确红一条。
第 2 条同理，红了"退回选择页"那条。）

### 4.5 一个 CSS 特异性坑（探针脚本抓出来的）

`.item.active .item-del` 和 `.item:hover .item-del` 特异性**完全相同**（都是 3 个类选择器），
所以后写的赢。原顺序让"当前项"排在后面 → 鼠标移上去时 × 反而只有 0.55 淡显：
**最该点的那一行最不清楚**。修法是把 `.item.active` 那条写在前面。

这个是拿真鼠标（CDP `Input.dispatchMouseEvent`）跑 `:hover` 时发现的，看代码看不出来。
冒烟里因此有两条真悬停断言：
「左栏已展开、这一行有真实尺寸（否则下面的悬停等于没测）」+
「悬停当前打开的那一条时 × 也要全亮」。

> 那次假红也值得记：前面广播小节会把左栏收成图标条，`.sidebar-full` 不显示，
> `getBoundingClientRect()` 全是 0，鼠标等于移到了左上角 ——
> 所以断言前面必须先**显式展开左栏**，并且卡一道"这一行真的有尺寸"。

## 2026-09-30 修订 5：设计系统与版式重做（用户：「页面还是太素，布局也不够好」）

这一版不是"再调一次颜色"，而是把三件事按顺序重做了一遍。顺序很重要，
**倒过来做会返工**：没有令牌就改不了版式，没有覆盖检查就不知道改漏了哪块。

### 5.1 先令牌化：不然改一次版式要全文搜索

旧 `style.css` 里散着 `13px` / `#e8e7e3` / `8px` / `rgba(0,0,0,.06)` 这类魔法数字，
同一个"次要文字色"在七个地方各写一遍。结果就是：想统一次要文字色 →
得先全文搜索再逐个判断是不是同一个语义 → 改完还是有一处漏掉。

现在 `:root` 里九组令牌，规则里只引用变量：

| 组 | 令牌 | 说明 |
|---|---|---|
| 表面 | `--bg` `--surface` `--surface-2` `--sunken` | 底 / 卡 / 次级 / 凹陷。**底色从纯白改成浅灰**，卡片才是白的 —— 有了"底"，卡片才浮得起来 |
| 线 | `--line` `--line-2` | 分隔 / 控件边框 |
| 文字 | `--text` `--text-2` `--text-3` | 主 / 次 / 三级 |
| 状态 | `--run` `--done` `--fail` `--idle` | 沿用 §6 定稿，不随主题变 |
| 品牌 | `--brand` `--brand-2` `--brand-3` `--brand-ink` `--grad` … | 修订 3 定的青→蓝→紫 |
| 间距 | `--s1..--s8`（4/8/12/16/20/24/32/44） | 4 的倍数，够用且不会有人随手写 `7px` |
| 字号 | `--t-xs..--t-2xl`（11/12/13/15/18/23） | 六档，用完为止 |
| 圆角 | `--r1` `--r2` `--r3` `--r-pill` | 6/10/14/999 |
| 阴影 | `--sh1` `--sh2` `--sh3` | 只表达"浮起多少"，不做花活 |

**★ 一条硬契约：JS 内联样式引用的变量名不许改。**
`app.js` 里有 `style="color:var(--text-dim)"` / `var(--text-faint)` / `var(--fail)` / `var(--run)`
这类内联引用。它们在 CSS 里改名**不会报错**，只是颜色悄悄回落到默认值 ——
是那种"没人会注意到、直到有人抱怨某个数字看不清"的坏法。
所以新版把它们保留成别名：`--text-dim: var(--text-2)`、`--text-faint: var(--text-3)`。

### 5.2 版式：每个视图都是「头 / 内容 / 底座」三段

原来只有"顶栏 + 左栏 + 一堆 div"，没有分区概念 —— 会话视图中间一大片空白、
左栏挤成 156px 连标题都被截断、任务视图的卡片从屏幕最左边开始铺。

| 区域 | 改版前 | 改版后 |
|---|---|---|
| 顶栏 | 52px，品牌名 + 工作目录平铺 | 52px，**品牌（图标+渐变字）/ 面包屑 / 工作目录 · 权限档·成员·编辑器**；底线一条品牌色渐变（修订 3 的"科技感"就靠它和 HUD，不再加别的） |
| 左栏 | 156px，一行条目 | **248px**，条目两行；分组标题带「清空」；**底部固定「回到选择页」** |
| 主区 | 内容直接铺满 | 三种视图各自有「头 / 内容 / 底座」，高度与滚动归属明确 |
| 编辑器 | 184px | 320px（可拖拽 160–520） |

几个具体决定，每个都对应一个真实的不好用：

1. **左栏条目改两行**。单行版在 156px 里连 `Qoder + Cursor` 都放不下，只剩省略号 ——
   用户认不出哪条是哪条，只能点开猜。现在第一行是名字（截断也不影响识别），
   第二行是「成员 · N 条对话」，跑着时补一句「运行中」。
2. **「回到选择页」压到侧栏底部**。它是"离开"动作，不该跟"新建"抢同一块注意力
   （旧版就挨着新建按钮，还挤在第二行）。
3. **面包屑**。顶栏原来只有品牌名 + 工作目录，而工作目录在会话 / 协同 / 选择页三种状态下
   **一模一样** —— 从截图里根本看不出这一屏是什么。现在三条分支与 `renderMain()` 一一对应
   （选择页 / 会话 › 成员 / 协同 › 任务名），不许出现第四种说法。
4. **空会话给"起点卡"**。旧版只有一句「发一条指令开始。」悬在一大片白里：
   用户既不知道该说什么，也看不见自己现在是什么档（而档位直接决定它能不能改文件）。
   现在给三样东西：跟谁说话、这一档意味着什么、三条点一下就能用的示例。
   **★ 示例只填进输入框，绝不自动发送** —— 自动发送等于在用户还没看清第一个字的时候
   替他花掉一次真实调用。这条有专门的打桩断言盯着（见 §5.7 变异 M17）。
5. **首页底部「接着上次」**。原来是一大片空白。这里放的是**真能一键继续**的入口，
   用的就是左栏那两条 `open-chat` / `open-task`，不新开通道；空列表时整块不出现。
6. **协同任务头补数字与进度条**。原来只有一排状态徽章，"跑到第几步、花了多少"
   要去数卡片。进度按**已处理**（成功+失败+未执行）算，不按成功算 ——
   否则一个 3 步全失败的任务看起来永远停在 0%。

### 5.3 三个"不报错但是错的"，都是这次自己抓到的

这三个的共同点：**界面照常渲染、冒烟也全绿，只有人眼看图才发现不对**。

1. **`plan-row` 被写成了 `display: grid` 四列**，而模板里那一行的子元素是
   `.inline`（整条操作栏）+ 标题 + 警告 + 指令框 —— 四件东西被塞进四个列里，整张
   执行计划确认表会散架。教训：**样式自己以为的结构必须和模板真实结构对齐**，
   这类不一致没有任何关卡会红。
2. **`<span class="prog-fill">` 的 `width` 完全不生效**。`<span>` 只有在 flex / grid
   容器里才会被 blockify；`.prog` 里没有 flex 上下文，所以它保持 `inline`，
   而 inline 元素**无视 width / height** → 进度条永远是一条空槽。
   修法是显式 `display: block`。（`flex: 1 1 100%` 写在 `.prog` 自己身上只解决
   它作为**子项**的尺寸，管不到它的**子元素**。）
3. **渐变标题被拉宽后发灰**。`.hero` 是纵向 flex，默认 `align-self: stretch`
   把标题盒子拉到整行宽 —— 而它的背景是一条 `8%→58%→100%` 的横向渐变，
   盒子一宽，真正有字的那一段就落进渐变中段，标题变成一片浅色。
   修法 `align-self: flex-start`。
   > 这个是**放大 2 倍截图**才看清的：1440px 的原图缩到 1080 看，
   > 渐变被当成"抗锯齿导致的发虚"，差点误判成"渐变字在浅底上就是不好看"。

### 5.4 安全网：样式覆盖检查器 `tools/check-css-coverage.mjs`

**为什么需要它**：界面冒烟 149 条断言盯的全是**行为**（点了有没有反应、状态对不对），
一条都不管"这块东西长什么样"。于是改版最典型的翻车是：模板里写了 `class="chat-head"`、
样式表里忘了定义 —— 元素照样渲染、功能照样可用、冒烟全绿，只有人眼能看出这块没样式。
反过来也一样：样式表里躺着早没人用的死规则，谁也不知道能不能删（于是谁也不敢删）。

它把两件事都变成可检查的：**用了但没定义 = 缺陷（红）**、**定义了但没人用 = 卫生问题（只列）**。

几条踩出来的规矩：

- **抽取必须有上下文**。第一版"把源码里所有带引号的短标识符都当类名"，于是
  `data-act="del-chat"` 这类**动作名**被当成 class，一次报 22 个假缺口。
  现在只从三处抽：`class="..."` 属性内部、`classList.add/remove/toggle/contains('x')`、
  `.className = ...`。
- **抽 `${...}` 之前先删掉比较表达式**。`class="home-tab${tab === 'solo' ? ' on' : ''}"` 里
  `'solo'` 是和 `tab` 比的值，不是类名 —— 不删就报一个假缺口 `.solo`。
- **一个字面量里可以写多个类名**。`${wide ? 'modal wide' : 'modal'}` 必须按空白拆开；
  第一版 `add('modal wide')` 因为含空格被整条丢掉，`.modal.wide` 一直被误报成死样式。
- **白名单要自带失效条件**。第二类白名单（"确实在用、但拼接方式让抽取器看不见"）
  每条必须带一个 `evidence` 正则，在源码里搜不到就报**错误**并计入退出码 ——
  逼着人来删。白名单烂掉的原因从来不是"有人塞了假条目"，而是"没人再回头看它"。
  目前只有一条：`.run`（由 `{ run: 'run', … }` 映射表注入，静态抽不出来）。

**顺带修掉两处写法**：`openModal(html, wide = false)` 把 `'modal wide'` 写死在字面量里、
`toast()` 把 `'toast err' / 'toast ok' / 'toast'` 写成字面量。两个都是"为了让检查器看得见"
而故意啰嗦一点 —— 一个会误报的检查器很快就会没人看。

## 2026-09-30 修订 6：角色目录统一 · 协同工作台 · 界面填 Key

用户这一轮说了四句：「页面太素，增加科幻感」「协同任务单独开一个页面，左侧选择主脑类似的分工
（分工再详细点）」「补充 Trae 和豆包」「软件还是太简陋，自己看看有没有需要优化的，或者 bug」。

### 6.1 ★ 先修底座：测试红着的时候，后面每一步都判断不了

上一轮"任务页改左右两栏"时漏改了几条断言，加上一个**真 bug**，底座是红的：

**浏览器进程泄漏（真 bug，不是测试的错）。** `tests/lib/browser.mjs` 原来写死
`--remote-debugging-port=9333`。Edge 的启动器进程是**分离**的，`child.kill()` 只杀掉那个
已经退出的壳，真正的 broker 继续活着占着 9333。于是下一次跑，`launchBrowser` 以为起好了，
`newPage` 其实开在**旧浏览器**上 —— 那个实例带着上一轮的 localStorage，恢复出上次停的会话，
首页整个不渲染。表现出来是"卡片 0 张"这种**和真实回归长得一模一样**的假红。
实测泄漏了 6 个浏览器实例、52 个 msedge 进程、9 个临时配置目录。

两道防线，缺一不可：

| 防线 | 做法 | 为什么不能省 |
|---|---|---|
| 让浏览器自己挑端口 | `--remote-debugging-port=0`，起完从私有配置目录的 `DevToolsActivePort` 读回真实端口 | 两个浏览器不可能再抢同一个端口，并发跑测试从"靠约定错开"变成天然安全 |
| 认端口归属 | 拿 `/json/version` 回给我们的 `webSocketDebuggerUrl` 与配置目录里那条**对账**，对不上当场报错 | "端口通了"不等于"是我们的"。这类"连到别人家浏览器"只能靠证伪，不能靠祈祷 |

关闭顺序也有讲究：先 `Browser.close`（让浏览器自己把渲染器/GPU/网络进程整棵树带走），
关不掉才退回 `taskkill /PID <pid> /T /F`。删配置目录要重试十次 ——
`Browser.close` 之后调试端点立刻消失，但浏览器还在收尾、文件句柄还没放，`rmSync` 会 EBUSY。

### 6.2 ★★ 角色这件事，原来写在三个地方，而且已经漂出了一件真事

前端一份数组（6 个，含「执行者」）、`base.js rolePrompt()` 一份预设表（5 个）、
`planner.js` 提示词一段硬编码列表（5 个，只写名字不写含义）。三份互相漂移，
最要命的是：**前端下拉框的默认值「执行者」，在 `rolePrompt()` 里没有预设** ——
于是"用默认角色"这条最常见的路径，落到模型头上的只有一句兜底的话。

现在只有 `src/roles.js` 一份，每条带 `label / glyph / duty（职责）/ deliverable（交付物）/
needs（能力要求）/ write（是否改文件）/ prompt（系统提示词）`，共 9 条：
代码主笔 ⌘ · 评审 ⌕ · 测试 ✓ · 文档书写 ¶ · 调研 ◎ · 架构设计 ⬡ · 重构清理 ⇄ · 汇总交付 ⊞ · 执行者 ▶。

> **为什么"只有一份"本身不会自动保持**：只要有人再往 `rolePrompt()` 里加一个 `if`，
> 漂移就回来了，而且**不会报错** —— 界面上照样有那个角色，只是系统提示词悄悄变回兜底。
> 这类失败全都不出声，所以 `tests/roles.test.mjs` 专门拿断言把它顶住（9 条）。

### 6.3 协同工作台：一整页，左边定分工、右边看结果

原来这一屏只有一个 textarea 和一个下拉框 —— 用户根本不知道"分工"这件事存在。现在是 `.wb` 两栏：

```
┌ 左栏 .wb-rail（316px）──────┬ 右栏 .wb-main ──────────────────────┐
│ 01 谁来拆解（主脑/代拆）    │ 目标 textarea + 拆解按钮 + 路径说明  │
│ 02 分工（9 个角色，每条带   │ ───────────────────────────────      │
│    职责 + 能力要求）        │ 05 分工预览：每个角色一张卡，        │
│ 03 成员池（不可用的也在，    │    写清 职责 / 交付物 / 谁能干        │
│    点一下就能填 Key）        │ 06 已有的协同任务（可跳回）          │
│ 04 执行参数（权限档/失败策略）│                                      │
```

**「分工再详细点」落在三处，都是能验证的：**

1. **左栏**每个角色写着职责 + `needs · 会不会改文件`（选人时看的是"这件事是什么"）；
2. **右栏预览卡**补上**交付物**与**谁能干** —— 交付物是验收标准，只写"负责测试"，

   不是写死的一句"可用"；
3. **计划确认表**每一行都带这个角色的职责/交付物，**当场**给出派活结论。
   规划者的提示词第 3/4 条一直在叮嘱模型别派错人，但结论从来没显示给用户看过 ——
   界面从来不把结论说出来的话，那两条约束等于只写给了模型看。

分工还会真的传下去：勾选的角色进 `POST /api/plan {roles:[…]}`，
规划者提示词里多出一段【指定分工】（"上面每个角色**至少**要出现在一个子任务里，
role 字段必须逐字使用这些名字"）；主脑那条路则写进 `.agenthub/inbox/*.json`。

**勾选顺序按目录归一。** 先点「文档书写」再点「代码主笔」，`state._roles` 里是
`[代码主笔, 文档书写]` —— 不归一的话，同一套勾选两个人看到两种顺序，发给引擎的数组也跟着乱。

### 6.4 契约：工作台必须保住的那几条

  2026-10-02 之前这里写的是 `value='workbuddy'` + 「交给主脑」，见文末修订 8。
- **`#goalBox` / `#plannerSel` 这两个弹窗 id 绝不能出现在工作台上**（有专门断言盯 id 撞车）：
  首页和弹窗在 DOM 里可能同时在，`getElementById` 只认文档顺序的第一个，撞了就是把弹窗里
  按的按钮算到首页的输入框头上；
- `.home-hud` 文本仍是 `ONLINE · n/m NODES`。

### 6.5 界面填 Key（Trae / 豆包）

`trae` 和 `doubao` 是"装了但缺密钥"：前者缺 `DOUBAO_API_KEY`，后者缺 `ARK_API_KEY`。
原来界面上只写着"请在项目根目录新建 .env"，用户得自己开编辑器、找到目录、写对变量名
（trae 那个变量名还反直觉）、再回来点重探 —— 每一步都能把人劝退。

现在点虚线卡（或成员池里那个 chip）就有密码框 + 「保存并重探」：
`POST /api/env` → 服务端白名单校验 → 原子写（临时文件 + rename）→ 设 `process.env` →
**真跑一次探活** → 直接返回刷新后的成员列表。写不进去或探不通，原样报实测原因。

**三条自我约束：**

| 约束 | 为什么 |
|---|---|
| **白名单**：`DOUBAO_API_KEY` / `ARK_API_KEY` / `CURSOR_API_KEY` / `QODER_PERSONAL_ACCESS_TOKEN` / `ANTHROPIC_BASE_URL` / `ANTHROPIC_AUTH_TOKEN` / `ARK_MODEL`，其余一律 400 | 这是个"往文件里写字"的接口，变量名不锁死就等于开了个任意写入口 |
| **拒绝含 `\r` / `\n` 的值** | 不拒的话，一个值里塞个换行就能往 `.env` 里注入任意多行 |
| **不写 `.env.bak`、永不回显、日志不打** | 里面是明文密钥，多留一份就多一份泄漏面；原子写已经足够防写坏 |

> **★ 这一条要在文档里写明：填 Key 会把**明文**密钥写进项目根的 `.env`。**
> 服务只监听 `127.0.0.1`，值只落本机、不回显、不进日志 —— 但它确实是明文。
> 表单里也写了这句话，不藏在文档里。

界面侧对应的一条纪律：**值只去不返**。提交时立刻清空输入框（不让明文在 DOM 里等着被下一次
重渲染带出来），`state` / `localStorage` / 页面里都搜不到它。所以这个表单里**没有**
"已保存的 Key"可以显示 —— 那是有意为之，不是没做完。

## 2026-09-30 修订 7：桌面快捷方式"打不开" —— 两个叠加的 bug

用户的原话是**「快捷方式打不开啊」**。这一条和界面设计本身没关系，但它是这一轮
唯一的"用户当前用不了产品"级故障，而且**两个病因是叠着的**：修掉第一个之后，
第二个仍然会让窗口白掉，只是复现条件变窄了。记在这里，因为两者的成因都是
"某个地方在撒谎"，而这正是这份文档一直在管的事。

### 7.1 白屏：存档里缺 `cards`，渲染在第一天就抛异常

用户在**旧版本**里存下的任务没有 `cards` 字段（那个字段是后加的）。
`renderTaskView` 直接 `task.cards[picked]`，于是
`TypeError: Cannot read properties of undefined (reading 's1')`。

致命的地方不在这一行，而在**没有东西接住它**：渲染是
`renderTopbar(); renderSidebar(); renderMain(); renderEditor()` 一路串下来的，
中间抛一次，`#main` 就停在"还没填内容"的状态 —— 剩下的什么都不执行。
而 `state.active` 是**持久化**的，所以每次打开都停在同一个坏任务上：
不是偶发，是**每次必白**，且界面里没有任何入口能清掉存档，人被彻底锁在外面。

三处改动，分别封三个口子：

| 改动 | 封的是哪个口子 |
|---|---|
| `normalizeTask()` / `normalizeChat()` 进 `loadState()` 边界 | 8 个以上的读取点，一次全修 |
| 缺 `cards` 时按 `plan.subtasks` 补占位卡 | 老任务仍然看得见自己的步骤，而不是空左栏 |
| `renderMainSafe()` 兜住渲染异常 | **任何**渲染错误都不许再白屏 |

补占位卡有一条硬规矩：**不编状态**。`subtasks` 里记着 `done` 就显示已完成，
没记过的一律显示「等待」—— 宁可少说，不许把一个没跑过的步骤显示成跑过了。
崩溃面板则必须同时说出三件事：数据还在（会话和任务在本机存档里）、
这是界面代码的问题（不是用户操作错了）、以及"清掉本机存档"会丢什么。
把原始堆栈印在面板上，是因为**看得见才修得掉**。

### 7.2 ★★ 时好时坏的"打不开"：启动横幅会为每一次失败尝试各印一份

第二个 bug 更难查，因为它**靠手点永远复现不出来**。

`ui/server.js` 的顺延逻辑（8787 被占就试 8788，最多 10 个）本身是对的，
错的是**播报**：横幅写在 `server.listen(port, host, cb)` 的回调里，
而那个回调本质上是 `once('listening')`。EADDRINUSE 的那次尝试不会触发 listening，
**但它的回调已经注册上去、不会因为失败被摘掉**；等顺延后的那次真的绑上时，
listening 只派发一次，却把攒下来的**所有**回调都跑一遍，每个闭包里装着它自己那一次的 `port`。
实测（顺延两级）：

```
端口 8790 被占用，试 8791…
端口 8791 被占用，试 8792…
  → http://127.0.0.1:8790      ← 假的：这个端口是别人的
  → http://127.0.0.1:8791      ← 假的
  → http://127.0.0.1:8792      ← 真的
```

`electron/main.js` 在日志里**只认第一个** `http://` 就把窗口指过去
（那里还有 `navStarted`「只许导航一次」的约束，是之前修 ERR_ABORTED 时加的），
所以只要走了顺延这条路，壳就**百分之百**导航到那个已经被别人占着的端口：

- 占着它的是上一次残留的实例 → 窗口显示**旧实例**的界面（看不到任何报错）
- 占着它的是别的东西、或那个进程刚退 → 连不上，只有空白或失败页

而"8787 被上一次的实例占着"恰恰是日常最常见的启动场景（`electron/main.js`
自己的注释里就写着"本机 8787 常常被上一次的实例占着"）。于是它的表现是
**时好时坏的"打不开"**：把残留进程关掉、再点一次快捷方式就好了 ——
**于是永远查不到病因**，而且"重开一次就好了"会让人以为是运气。

两处都改：

| 位置 | 改动 |
|---|---|
| `ui/server.js` | 横幅只挂**一个** `once('listening')`，端口从 `server.address()` 读 —— 那是绑定结果本身，不是"我以为我要绑哪个" |
| `electron/main.js` | 抽出 `bannerUrl()`：取**最后一个**匹配，且要求端口号后面**紧跟换行**（整行到齐才认）。取最后一个是防横幅再重复；要求换行是防 `out` 流式累加时停在 `http://127.0.0.1:87` 这种**合法但错误**的半截匹配上 |

新增 `tests/listen-banner.test.mjs`：占住一个端口，真的起一个服务进程，
断言横幅只印**一份**，且那份报的端口上真的有人能应答（`fetch` 得通），
而**我自己占着的那个端口不是它报的**。这条断言盯的是事实，不是那句话 ——
修复前跑它，报出来的恰恰是被占住的端口。

### 7.3 这一轮验到了什么

| 关卡 | 结果 |
|---|---|
| 单元测试 | **256 / 256**（新增 `tests/listen-banner.test.mjs`） |
| 界面冒烟 | **212 通过 / 0 失败** |
| Electron 壳冒烟 | **14 / 14**（开发路径） |
| 打包产物冒烟 | **14 / 14** |
| 占位服务验尸 | 8787 被一个"故意印着『这是占位服务』的服务"占住时启动打包产物：窗口落在 **8788**，标题 `AgentHub`，主区有内容，无崩溃面板，**页面里不出现占位服务的文字**；8787 空着时落在 **8787**。两条都过 |

验尸这一步值得单独说：光断言"窗口里有内容"是**不够**的 —— 修复前的表现恰恰是
"窗口里有内容"，只不过那是**别人**的页面。所以占位服务必须带一个独一无二的
内容特征，断言盯的是"这页不是别人家的"。

## 2026-10-02 修订 8：默认拆解者 = 成员，不再是主脑

用户原话：「为什么是这样的，我想要那种可以直接在该软件工作的类型」（附「已交给主脑」弹窗截图）。

### 8.1 这不是 bug，是默认值选错了对象

弹窗没错、落盘没错、那句可复制的话也没错 —— 错的是**默认把用户推到一条他走不通的路上**。

再给用户一句话，让他**切到 WorkBuddy 里粘**」。

默认值是主脑，所以用户第一次打开看到的就只有一个「要我去别的软件」的按钮 ——

| `plannerHintText()` | 主脑那条明说「想就在本软件里干活，就换成上面的成员」 |

外加一条**退路**：「已交给主脑」弹窗里多一颗「改用本软件里的成员来拆」（`case 'plan-in-app'`）——

主脑**仍留在候选里**（想走 MCP 反向通道的人有门），只是不再当默认。

## 2026-10-02 修订 9：跑动中的开销 —— 增量重画 · 通道心跳 · 拆解上限

用户原话：「再看看有没有可以优化的地方，比如页面，分工，速度之类的」。
三项都动了代码，每项都配了**能红**的断言。

### 9.1 ★★ 任务视图：只重画变动的那一块

**原来的样子**：每个事件末尾都调一次 `render()`，而 `render()` 会把顶栏、左栏、主区、
编辑器**全部**重建一遍；主区那份又是整块 `innerHTML = <一大串字符串>`。
一个几十步、日志攒到几百行的任务，每来一个事件就要重拼这份字符串、
让浏览器重新解析上千个节点 —— 而事件是成串来的（开始、工具、结束…），
同一帧里能重画好几轮，用户看到的就是卡顿。

**改法**：把任务视图拆成四块，各记各的"当前长相"，只在真的变了的时候替换：

| 块 | 什么时候重画 |
|---|---|
| 日志区 | 只往后**追加**新增的行（最大的一块，也最容易省） |
| 分工列表 | 只换状态变了的那个条目 |
| 任务头 | 那组数字变了才换 |
| 右栏 | 选中的那一步变了才换 |

顶栏与编辑器在任务跑动期间不受影响，直接不画；左栏只在任务状态真的翻转时重画。
**兜底**：任何一处"对不上结构"（不是这块任务、步骤名单换了、DOM 被别处重建过…）
一律退回整屏重画 —— **宁可多画一次，也不能少画一条**。

**断言钉的是节点身份，不是长相**（冒烟 11b2）：没变的那一步必须是**同一个 DOM 节点**，
日志区同理。只断言"看起来对"是拦不住"整屏重建"的 —— 而整屏重建正是这次要修的东西。

### 9.2 通道心跳：长任务中间不许静默

成员调用一次动辄几十秒（有的成员默认超时 10 分钟），这段期间 SSE 通道上**一个字节都没有**。
被掐掉的失败方式是最坏的一种：**连接没了，任务其实还在服务端跑**，
界面停在半路 —— 用户要么以为跑完了、要么以为卡死了，两种判断都是错的。

改法是在通道上每 15 秒写一条 **SSE 注释行**（以 `:` 开头）。协议规定客户端必须忽略它，
所以它顶得住空闲超时，又不可能混进事件里；比"发一个假事件"干净 ——
后者是在协议层撒谎，前端得为一条谁都不认识的事件类型加分支。

验收物是 `tests/sse-heartbeat.test.mjs`：把间隔压到 3ms，用一个**零成本假成员**
（本机 node 跑一段"睡 1.2 秒再回 ok"的脚本）真跑一次，然后逐行看原始响应 ——
心跳必须在、data 帧一条不坏、收尾事件必须到。
它同时断言**窗口确实 ≥1 秒**：窗口不存在时，报的是"这次压根没跑够久"，
而不是一句容易被忽略的"没看到心跳"。

> ⚠️ 这个测试**不能**用真成员：要么花钱（claude / codex），要么依赖本机装没装（trae / dsh），
> 一个会被"环境变了"影响的断言迟早变成假绿或假红。
> 所以给服务端加了一个 `AGENTHUB_MEMBERS` 开关（指到另一份成员配置），默认行为与以前完全一致。

### 9.3 拆解的两条上限，跟着规划者走

「子任务 2-6 个」「每条 prompt ≤150 字」是**为一次真实事故加的**：
规划模型的输出写到一半被截断，后面的子任务整个丢掉（见 docs/05 第七节）。
但那是"一次性吐出整段"的模型的毛病 —— codex 的 `exec --json` 是逐事件回来的，
不存在"写到一半没了"。对它继续压这两条，等于白扔掉规划能力：
拆得少、指令写得含糊，反而更容易在**执行**阶段失败。

实现上没有在引擎里硬编码成员 id（引擎本来就不该认识具体成员），
而是给适配器加了一条声明 `streamsStructuredOutput`（默认 `false` —— 没声明就当会截断），
规划提示词按它选口径。**两边都有断言**：放宽的那边要真的放宽，
默认那边要一个字都没动 —— 不然就是拿别人的安全换这边的能力。

## 2026-10-02 修订 10：回车发送（原来只有 Ctrl+回车，而且没人告诉你）

用户原话：「enter无法发消息」。

**这不是 bug，是一个"没有出口的设计"**：发送快捷键一直是 **Ctrl/Cmd+回车**，
而**界面上没有任何一处写过这件事** —— 输入框下面那行只有权限档位的说明。
用户按回车没反应，唯一能得出的结论就是"这个软件发不出消息"。
一个必须靠猜才能发现的快捷键，等于没有这个快捷键。

改法按聊天软件的通例来：

| 按键 | 行为 |
|---|---|
| 回车 | **发送** |
| Shift+回车 | 换行（长指令照样写得成多行） |
| Ctrl/Cmd+回车 | 照旧发送（老习惯不用改） |

并把「回车发送 · Shift+回车换行」写进输入框下面那行提示 ——
发现成本从"猜"降到"看一眼"。

### ★ 一处必须让开的地方：中文输入法

打中文时，**回车是"选定候选词"，不是"发送"**。
合成期间浏览器会把 `isComposing` 置真，有的输入法只给 `keyCode === 229` —— 两个信号都要认。
不认识它，打中文就变成"每选一次词、发半句话"，那比原来按不动还难受。

冒烟新增 10b 节 5 条断言：回车真的发得出去（草稿被清空、气泡 +1）、
Shift+回车不发送、**合成期不发送且已打的字要留着**、提示里必须写着发送方式，
外加一条"输入框确实拿到了焦点"—— 拿不到焦点的话，后面几条全是空过。
