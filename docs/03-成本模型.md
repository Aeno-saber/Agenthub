# AgentHub 成本模型与优化

> 数据来源：本机实测，2026-09-29。所有数字都用 `claude --output-format json` 返回的
> `usage.input_tokens` / `total_cost_usd` 记账，不是估算。

---

## 结论（先说）

1. **每次调用有约 18.6k input tokens 的固定开销**，与任务内容基本无关。
   它来自 Claude Code 自身的系统提示 + 内置工具 JSON Schema —— **不是我们的配置造成的**。
2. 用户侧配置（skills / plugins / CLAUDE.md 等）只占其中约 **520 tokens（2.8%）**。
3. 启用 `--bare` 后，单次调用 input tokens 从 **18,577 → 1,285（降 93%）**，
   完整协同任务实测成本 **$1.0621 → $0.2851（降 73%）**。
4. `--bare` **没有砍掉任何工具能力** —— 已实测文件读写与命令执行都正常。

---

## 一、固定开销到底花在哪（对照实验）

同一句 prompt（`Reply with exactly: OK`，2 tokens 输出），只切换"最小化开关"：

| 变体 | input tokens | 花费 | 相对默认 |
|---|---|---|---|
| ① 默认（完整配置） | **18,577** | $0.0929 | — |
| ② `--safe-mode`（跳过全部自定义配置） | 18,057 | $0.0903 | −2.8% |
| ③ `--exclude-dynamic-system-prompt-sections`（精简环境段） | 18,530 | $0.0927 | −0.3% |
| ④ `--bare`（极简模式） | **1,285** | **$0.0065** | **−93%** |

**怎么读这张表**：

- ② 把用户的自定义配置**全跳过**，只省下 520 tokens → 用户的 skills / plugins / CLAUDE.md
  根本不是大头。
- ③ 精简动态环境段（cwd、git 状态、平台信息等），只省 47 tokens。
- ④ 一次性砍掉 17,292 tokens（18,577 − 1,285）→ 大头在别处。

**逐项拆开**（把默认的 18,577 当 100%）：

| 成分 | tokens | 占比 | 怎么算出来的 |
|---|---|---|---|
| Claude Code 系统提示 + 内置工具 JSON Schema | ≈**16,725** | **90.0%** | 扣除下面三项后的余量 |
| 最小请求体（`--bare` 也砍不掉的底） | 1,285 | 6.9% | ④ 实测值 |
| 用户自定义配置（skills / plugins / CLAUDE.md） | 520 | 2.8% | ① − ② |
| 动态环境段（cwd / git / 平台信息） | 47 | 0.3% | ① − ③ |
| **合计** | **18,577** | 100% | |

也就是说：**每一次调用，光是把 Claude Code 自己的说明书和工具清单递过去，就要花掉九成。
我们写的代码和用户的配置，加起来不到 3%。**

> ⚠️ 记账口径提醒：本表是**裸调用**（无角色提示词）。
> 经 AgentHub 适配器调用时会多带一段 `--append-system-prompt`（角色提示词），
> 所以实测是 **19,629 tokens** —— 比裸调用多约 1k，这才是"每次调用的固定成本"。

复现：`node tests/token-breakdown.mjs`

## 二、优化前后：真实协同任务

两次都是 **3 个子任务（2 个并行 + 1 个汇总）、claude、execute 档、同样规模**的编码任务：

| 批次 | 目标 | 结果 | input tokens | 输出 tokens | 耗时 | 花费 |
|---|---|---|---|---|---|---|
| **优化前** | 给 `plan.js` / `trace.js` 补单测 | 3/3 | 65,842 | 18,386 | 68.5s | **$1.0621** |
| **优化后**（`--bare`） | 给 `planner.js` / `orchestrator.js` 补单测 | 3/3 | 11,799 | 8,387 | 52.3s | **$0.2851** |

**降幅：成本 −73.2%，input tokens −82.1%，耗时还快了 24%。**

单子任务明细（优化后）：

| 子任务 | 状态 | 耗时 | 花费 | input | output |
|---|---|---|---|---|---|
| s1 `planner.js` 单测 | ok | 25.0s | $0.0833 | 4,312 | 2,184 |
| s2 `orchestrator.js` 单测 | ok | 21.1s | $0.0869 | 4,303 | 2,383 |
| s3 测试覆盖说明 | ok | 27.3s | $0.1149 | 3,184 | 3,820 |

对比优化前单子任务 `plan.js` 的 **24,247 input tokens** —— 这就是固定开销被反复支付的样子。

轨迹存档：`.agenthub/runs/run-1790658473692.json`（前）、`run-1790658772010.json`（后）

## 三、`--bare` 会不会砍掉能力？（必须验证）

便宜但残废等于没优化。实测 `tests/verify-bare.mjs`：在 `--bare` 下让它
① 创建 `.agenthub/bare-test.txt`，② 运行命令读回内容。

**硬证据**：

- 文件真实存在：`.agenthub/bare-test.txt`
- 内容：`bare-mode-works`
- `--allowedTools Bash Read Write Edit Glob Grep` 一个都没少

→ `--bare` 砍的是**系统提示文本**，不是**工具本身**。

## 四、对引擎的几条策略

1. **默认给 claude 挂 `--bare`**，写在 `src/config/members.json` 的 `baseArgs` 里。
   已经生效，改造点是 `src/adapters/claude.js` 的 `...this.spec.baseArgs`。
2. **子任务不要拆太碎**。每次调用都要重付一份固定开销，拆成 6 个 3k 的活
   比拆成 3 个 6k 的活更贵。经验阈值：单个子任务预期产出 ≥ 1 个文件或 ≥ 5 行结论再单列。
3. **预算闸必须保留**（`--budget`）。成本与任务规模非线性相关，靠预估不如靠闸。
4. **其他成员要用各自的等价开关**（Cursor / Qoder / Trae 没有 `--bare` 对应物，
   接入时必须单独实测其固定开销，不能照搬 claude 的数字）。
5. 上下文传递也有成本：`buildPrompt()` 会把上游产出注入下游 prompt，
   超长产出已做截断，截断阈值直接决定成本。
